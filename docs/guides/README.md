# Guides

How-to documentation for contributors. Task-oriented — answers "how do I do X?".

## What goes here

Task-oriented docs that walk a contributor through doing something. Each guide should:

- Open with the goal in one sentence
- List prerequisites
- Walk through the steps with concrete commands
- End with how to verify it worked

## What does NOT go here

- Reference material (every config option, every endpoint) → `../api/` or per-tier docs in `../architecture/`
- Deployment / production ops → `../operations/`
- Why we chose a tool → `../architecture/decisions/`
